<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser-beta → API (CORS) | Origin é dado do navegador, não prova identidade; auth continua cookie httpOnly + requireAuth |
| client → PATCH projects/:id | referenceSearchId vindo do body é hostil; servidor valida uuid + pertencimento ao projeto/owner |
| client → GET runs/:runId/results | runId é hostil; escopo por owner, fora do escopo vira 404 sem oráculo |
| migrate → PG DEV | MIGRATION_DATABASE_URL é segredo; nunca em log, código ou resposta |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Spoofing | CORS origin | mitigate | allowlist exata de env, sem `*`/regex/espelho; curl válido vs adulterado no verify |
| T-06-01-02 | Tampering | PATCH referenceSearchId | mitigate | Zod uuid + check search.projectId + owner no servidor; estranho/adulterado → 404 idêntico |
| T-06-01-03 | Information Disclosure | GET results isNew | mitigate | listResultsForActor escopa por projects.ownerId; 404 sem distinguir inexistente vs alheio; sem rawMetadata com segredos |
| T-06-01-04 | Information Disclosure | CORS + credentials | mitigate | credentials:true só com origem exata; Vary: Origin; sem log de Authorization/cookie |
| T-06-01-05 | Elevation | ownerId do body | mitigate | ownerId sempre de request.actor; nenhum campo owner aceito do cliente (padrão projects.ts) |
| T-06-01-06 | Denial of Service | priorRows anti-join | accept | query por search com índice existente; paginação clamp 1..100 já vigente; sem N+1 (um Set por request) |
</threat_model>
